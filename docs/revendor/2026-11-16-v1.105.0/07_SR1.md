## The title-bar pass, per window

This addon draws three windows of its own. Each title bar carries one control, its close, built by
`modules/Browser_Chrome.lua` `B:MakeCloseButton`; there is no lock, minimize, settings, export or
other title-bar mark, and the ledger window's tabs are text tabs below the bar. The library's
windows (the debug console, the CSV copy window, the sim panel) are the library's pass.

| Window | Control | Tooltip | Rest | Hover |
|---|---|---|---|---|
| Ledger window (`BankLedgerWindow`) | close | "Close", above (PlaceAttached), `gtip.title` | `close.rest` = `icon.tint` | `close.hot` |
| Session window | close | "Close", above, `gtip.title` | `close.rest` = `icon.tint` | `close.hot` |
| Export modal (`BankLedgerExportWindow`) | close | "Close", above, `gtip.title` | `close.rest` = `icon.tint` | `close.hot` |

- Change: `B:MakeCloseButton` hooks `LibKa0s-Tooltip-1.0` `AttachTitleTip` on the button, its words
  `Tooltip.CloseTip(addonName)` read on each hover, owner `BankLedger`. `W.HeaderButtons` was not
  adopted: one hook in the one shared builder is the smaller change.
- Colors: no host change. The button already goes through the skin's `CloseButton` primitive, so
  the re-cut tag's `close.rest`, which follows `icon.tint` in every skin, reaches all three
  closes. The host's degraded copy keeps `close.rest` at Ka0s Default's gray, which is that skin's
  `icon.tint`.
- Degraded, with no LibKa0s, the close has no tooltip and still closes.
- Tests: `tests/test_title_bar.lua`, two cases. Every Button built on each window's title bar shows
  a non-empty tooltip on hover, owned and placed (`ANCHOR_NONE`), above the control, in
  `gtip.title`, hidden on leave, and the close says "Close" (red before the hook). Every close rests
  in `icon.tint` and lights `close.hot` under Ka0s Default and Obsidian.
