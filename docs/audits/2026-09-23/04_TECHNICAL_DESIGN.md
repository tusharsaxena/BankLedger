## BL-48 · The perf skip reason (upstream)

**Where:** `LibKa0s/testkit/run-automated-tests.sh`, the `perf` suite block (addon copy
`tests/_kit/run-automated-tests.sh:343-344`) and `md_perf_section` (`:833-848`).

**Shape.** `automated-tests-§3` sanctions two skip reasons and requires the second when it applies. The
runner needs a way to know. Two candidate discriminators, in order of preference:

- **Read the register** — a `| \`performance-§12\` |` row under `## Documented deviations` in
  `docs/ARCHITECTURE.md`. This is the one home the standard gives the exemption (`performance-§12`,

  per-repo configuration.

When the row is present: `NOTE[perf]` = *"performance-§12 no-combat-path exemption — no tests/perf.lua
by design"*, the manifest's `skipReason` names `performance-§12`, and `md_perf_section` emits a sentence
saying the addon holds the ratified exemption and pointing at `docs/performance.md`. When absent, today's
reason (1) text stands. Add kit self-tests for both branches.

**Consumer side:** re-vendor (whole folder), then run the four suites once so `RESULTS.md` is rewritten
by the new runner. Nothing is hand-edited.

## BL-34 · One global reset (owner decision first)

**Where:** `settings/Slash.lua` (`Sl:ResetEverything`, `Sl:CliResetAll`), `settings/Panel.lua`
(`P:RestoreDefaults`), `settings/Schema.lua` (`NS.COMMANDS` `resetall` row, `S:ComposeMaster`'s
`onResetAll`), `docs/ARCHITECTURE.md:505`, `README.md` (Usage and Troubleshooting), `tests/test_panel.lua`.

**Option A — unify up (the row's own proposal, and the only §12-compliant end state).** Every entry
point raises the confirm-gated `KA0S_BANKLEDGER_RESETALL`, whose `OnAccept` is `Sl:ResetEverything`:

- `P:RestoreDefaults` (the page Defaults and, through `OnDefault`, Blizzard's footer control) and the
  `resetall` verb call a shared `Sl:RequestResetAll()` that shows the popup (or, headless, runs the
  body). The destructive act is then never reachable without the confirmation, including from the
  un-gated footer control.
- `Sl:ResetEverything` restores the session-only rows by name — `state.debugConsole` and
  `state.testMode` — through their own `set`, without per-row `[Set]` lines (debug-logging-§10), and
  keeps the held `minimap` table.
- `Sl:CliResetAll`'s partial behavior disappears. If a non-destructive *reset settings, keep history*
  act is still wanted, it is a **separate, separately-confirmed** act with its own name (`options-ui-§12`
  forbids folding a store purge into *reset settings* only for an addon **with** a profile; here the
  whole store is the reset). `/bl purge` already exists for the history-only case.
- Tests: the blast radius — after the reset with two filter entries, a saved view and ledger rows, the
  store equals a fresh install's minus `minimap`; the session-only rows are swept; `SettingsChanged`
  published once. The two existing destructive-reset cases in `tests/test_panel.lua` extend to cover the
  footer route.
- Docs: README Usage (`:88-96`) and Troubleshooting (`:148`) re-worded — `/bl resetall` becomes
  destructive; the row at `docs/ARCHITECTURE.md:505` is deleted (this also closes `BL-34a`).

**Option B — unify down.** Point the button at `Sl:CliResetAll`. Leaves no wholesale reset, which
`options-ui-§12` requires for a no-profile addon, so it needs a **new** register row with a real
re-check trigger; not recommended.

**Risk.** Option A turns two non-destructive controls destructive. The confirm popup carries the
canonical *"…configured or recorded is discarded, for every character on this account — this cannot be
undone."*, so no path loses data unwarned, but the README change must land in the same release and be
called out in `## Version History`.
